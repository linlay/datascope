# DataScope 用户手册

## 从哪里开始

登录控制台后，先在左上角选择数据库。左侧菜单随当前库和平台账号的授权变化。要查业务数据，进入「查询工作台」；要执行已经定义好的业务操作，进入「动作工作台」。

首次接入一个库时，管理员可按以下顺序验收：

1. 在「增加数据库」登记数据源并测试连接。
2. 在「查询配置」选一张表，开放必要的字段，并配置可见行。
3. 在「查询工作台」用一位业务用户的身份查询，核对可见记录和字段。
4. 在「MCP 配置」启用所需工具，再用目标业务账号连接并验证。

配置表单采用上置标签，短且相关的字段最多并排两列，窄面板自动单列；长文本、SQL、脚本和参数表格保留整行区域。操作日志筛选使用左侧标签和按内容定宽的控件，窄屏自动换行或堆叠。桌面输入框与选择器高 32px、按钮高 28px，手机与触屏操作区域至少 44px。浅色和深色界面使用实心波浪背景与中性毛玻璃面板；键盘 Tab 导航保留清晰焦点外框，校验错误显示在对应控件下方。对话框正文独立滚动，标题与底部操作保持可见。细窄无边框滚动条在滚动或指针交互时显示，停止操作约 3 秒后隐藏。

## 数据库说明

「数据库配置 → 基本信息」分两列展示：左列为显示名称，右列为数据库类型及 SQLite 的「打开 DDL 管理」开关；第二行左侧为「描述」，右侧为「使用说明」，点击「查看」在弹框中阅读完整正文。这些配置项使用上置标签，下方显示内容。右上角依次为「存储详情」「编辑说明」「测试连接」「保存」。通过「编辑说明」修改描述和 Markdown 正文，切换预览核对后保存；需要 `config.read` 和 `config.write`。未保存修改在离开时会提示，两个字段均可清空。代码块的复制按钮悬停时浮在右上角，不占独立行；键盘聚焦与触屏也可使用。数据库文件路径和网络库的「编辑连接」入口位于「存储详情」内。「移除数据源」位于页面最底部，仅系统管理员可见；确认后移除登记并保留业务数据。基本信息、业务认证、本地账号等分组标题在滚动阅读各分组时保持置顶。

简介和完整说明保存在 `data/databases/<数据库 ID>/management/database.yml` 的 `database.description` 和 `database.documentation` 中，不写入业务表。说明面向当前库使用者，请勿填写内部凭据。其他页面顶部数据库选择器旁的「使用说明」按钮以对话框显示简介与完整使用说明；正文不占用工作台空间。SQL 示例只供复制参考，不自动执行，仍受当前身份的行列权限和返回行数限制。

业务 MCP 初始化提供简介及说明 URI；通过 `resources/list` 发现类型为 `database-documentation` 的资源，再用 `resources/read` 读取 `datascope://database/<数据库 ID>/documentation`，返回 `text/markdown`。读取需本库的 `query`、`action` 或 `knowledge.read` 能力之一；纯知识账号不能借此读取 HTML 视图。正文是业务参考资料，不是系统指令。完整说明按需读取，不随每次调用自动发送。保存后重新连接 MCP 获取最新初始化简介，资源读取使用当前配置。

## 演示数据库怎么用

当前本地的四个演示数据库是证券、区域销售、高校教务、渠道与社交媒体运营。在目标库点击“使用说明”，先确认数据日期和当前身份，再挑一个自然语言问题发送给已连接该库的 AI 客户端。控制台的查询工作台用于技术查询，不会自动把自然语言问题当作业务查询执行。

四份使用说明按照“了解业务—第一次提问—连续追问—切换角色—办理操作—解读结果”组织，给出可直接使用的问题，不把表结构或 SQL 当作入门要求。例如，可以询问“2026 年 10 月各地区销售目标完成得怎样”，再追问“把未达标地区按销售员展开”；高校教务可从“我的秋季课表”开始，渠道运营可从“有哪些待审核和发布失败的任务”开始。证券库的主要查询窗口为 2026 年 9 月 15 日至 10 月 20 日。

提问不能扩大账号的授权范围。需要修改数据时，先核对预览，再由具备权限的业务账号本人确认；区域销售演示数据库只做查询分析。技术人员仍可使用单独维护的 SQL 示例、业务知识与配置资料。新数据库通过配置包导入，已有库的说明通过正常配置保存流程显式更新，重复导入不会覆盖自定义内容。

## 数据库、账号与系统设置

管理员可登记网络数据库、创建或连接 SQLite，也可以上传 CSV 或 SQLite 文件。CSV 使用 UTF-8 编码，首行为列名，导入后的表名为 `data`，字段按文本保存。上传上限为 20 MiB。

网络数据库先在「数据库配置」登记 Schema 范围，再到「查询配置」选择要管理的表。切换顶部数据库后，先核对库名，再修改配置。通过顶部「增加数据库」选择「全新配置」手动填写，或选择「从已有数据库克隆」，选来源库并填写新库名称及连接。来源连接会预填供修改，密码需重新输入，SQLite 需填写目标文件路径；也可上传文件作为新库。克隆先创建独立的新库，再预览并确认复制表与字段配置、查询权限、Actions、知识、视图等所选范围，认证配置默认不选。网络库会先登记来源库已配置的表，目标必须存在兼容结构。来源库保持不变，不复制业务数据、密码、账号或授权；新库的 MCP 和写入默认关闭。克隆失败可在同一新库重试，或选择「保留新库，稍后配置」，不会再次创建。  编辑 Schema 范围时，已有动作写连接会同步默认 Schema 和允许范围，并保留独立写入账号、密码及 TLS 配置。

系统管理员可在「数据库配置 → 基本信息 → 存储详情 → 编辑连接」维护网络数据库的地址、端口、只读账号、密码和 TLS。密码留空保留原密码，新密码加密保存。点击「测试连接」检查草稿，再点击「校验并保存」；保存时会重新测试并检查已登记字段是否存在且类型、非空和主键属性兼容，失败时保留原配置及密码。已有动作写连接同步地址、端口和 TLS，保留独立的写账号和密码，并一并测试。修改期间若其他窗口保存了配置，请刷新后重试。成功保存保留数据源 ID、权限及业务配置，并记录审计日志。此入口仅用于同一业务库的维护，结构校验不能证明业务数据相同；切换实际业务库或数据库类型请新建数据源。SQLite 不提供此入口，库名及 Schema 范围不在此弹窗修改。

在「数据库配置 → 超时设置」分别设置「查询超时（秒）」和网络数据库的「连接超时（秒）」，需要 `config.read` 和 `config.write`。查询可填 1–120 秒，连接可填 1–60 秒；0 表示继承服务默认值，页面显示当前有效上限。未配置时默认查询 30 秒、连接初始化 10 秒。保存校验当前配置版本，新请求自动生效，无需重启；已开始的请求沿用原设置。连接超时覆盖网络连接初始化（连通性、只读事务校验和初始表目录），查询超时用于单次查询操作，包含连接池等待、SQL 执行和结果读取；权限前置检查单独使用查询超时，不是整个请求的统一总时限。客户端或外层请求可更早取消，增加查询时限不会延长客户端时限。超时错误会区分连接初始化、连接/事务获取、权限前置检查和 SQL 执行/结果读取；用户主动取消显示取消，不自动重试。服务默认值可通过 `QUERY_TIMEOUT=30s` / `--query-timeout=30s` 和 `CONNECT_TIMEOUT=10s` / `--connect-timeout=10s` 设置（两项分别不超过 120 秒和 60 秒），修改服务环境后需重启相应服务，Docker 需重新创建容器，API 与 MCP 服务应保持一致。

平台账号用于登录控制台，数据库授权决定可以看到哪些工作台、谁能编辑或试运行。业务身份用于计算数据可见范围和执行正式动作。在当前库配置业务认证、账号及能力；菜单缺失时，请管理员检查该平台账号在此库的授权。OneID 接入说明在「认证服务」选择框旁的帮助按钮中查看；使用全局提供方时，帮助按钮位于「认证提供方」旁。右上角「系统设置」可切换语言、外观，并按权限管理平台设置。

在「数据库配置 → 业务认证」选择「Token / API Key → 账号密码 / 业务 Token」并保存，开启该库 MCP 后，点击「登录并获取个人 Token」。独立登录页要求输入该库的业务账号和密码，不复用管理后台登录状态；成功后复制个人 Token，在客户端选择 Token → Bearer。有效期默认 1 小时，可选 24 小时、7 天、30 天、90 天、1 年（365 天）、自定义或「永久（直到撤销）」；自定义输入整数并选择分钟、小时或天，范围为 1 分钟至 365 天。永久 Token 不按时间过期；本地账号重置密码、禁用、修改权限或切换业务认证配置后，旧 Token 仍会失效。页面刷新或关闭后清除页面中的 Token。部署在 `/datascope/` 等子路径时，登录信息和 Token 接口均使用应用路径前缀；若提示接口返回无效数据，请检查反向代理是否将该前缀下的 `/auth/` 请求转发至后端，而非返回门户或前端 HTML。

## 查询配置、查询工作台与表数据

查询配置、数据来源、动作配置、知识配置和视图配置占满可用工作区，左右列表及编辑内容各自内部滚动，面板标题和操作按钮保持可见。查询配置的数据表列表最大宽度为 420px，可显示带 schema 的表名；宽屏剩余空间用于右侧详情。

在「查询配置」选择表，确定开放字段、行过滤条件和返回行数上限。行过滤入口始终显示：SQL 为空时标题为「行级过滤」，已有 SQL 时为「行过滤 SQL」。展开后可直接添加 SQL，填写内容会自动选择「使用 SQL 过滤」，清空则切换为「无需行权限过滤」。「前置查询准入 SQL」可用于设置查询前必须满足的条件及拒绝提示，留空则不进行这项检查。两处 SQL 无论是否已有内容，默认均折叠，标题旁以「已配置 SQL」或「未配置 SQL」标记是否已有内容，点击标题可展开查看和编辑，再次点击收起；折叠不影响策略生效或保存。用字段说明记录业务含义，对敏感字段配置脱敏。保存后用业务身份测试一条应可见的记录，再测试一条应隐藏的记录。

行过滤 SQL 决定可见的记录，前置查询准入 SQL 决定是否允许执行整次查询，两者独立。公共目录或字典表可选择「无需行权限过滤」并保留字段开放限制；如仅允许有效业务身份读取，仍需保留前置准入检查。仅选择字段、不限制记录的 SELECT 不需要作为行过滤 SQL 保存。

在「查询工作台」输入只读 SELECT，选择身份并执行。例如，库中有 customers 表时，可输入 `SELECT customer_no FROM customers WHERE customer_no = :number`，并在参数区填写 `{"number":"C001"}`。检查返回结果和改写后的 SQL，确认权限条件生效。具备全量查询权限的账号还可对照原始结果。

查询工作台和 MCP `query` 也支持 `SHOW TABLES`、`SHOW COLUMNS FROM customers`（别名 `SHOW FIELDS`）、`DESCRIBE customers`（别名 `DESC`）及 `SHOW INDEX FROM customers`（别名 `SHOW INDEXES`、`SHOW KEYS`）。这些命令返回平台统一元数据，不执行数据库原生 SHOW：表列表返回 `table_name`，字段返回 `field/type/not_null/primary_key/comment`，索引返回 `index`；只显示已启用表和开放字段，不返回全库记录数，限制字段时不返回索引。网络数据库可使用完整的 `schema.table`，省略 Schema 时使用默认 Schema；不支持 LIKE、WHERE 或其他 SHOW 子命令。`EXPLAIN SELECT customer_no FROM customers` 先执行原查询的权限校验和前置准入检查，再解释权限改写后的查询；支持 SQLite、MySQL/OceanBase 和 PostgreSQL，SQLite 另支持 `EXPLAIN QUERY PLAN SELECT customer_no FROM customers`。不支持 `EXPLAIN ANALYZE`、其他选项或写语句；配置字段脱敏的数据库暂不支持 EXPLAIN。全量查询和 MCP `raw_query` 支持相同诊断语法，沿用全量查询授权，EXPLAIN 不做行权限改写。诊断结果受行数上限、超时和审计约束，截断见 `truncated`。

要直接核对表中的记录，在「表数据」选择表并筛选记录。此入口需要全量查询权限；验证某个业务用户实际能看到什么，请在查询工作台使用该身份。

## 数据来源、导入脚本与定时任务

「导入列表」与「导入详情」顶部对齐，列表及详情内容各自滚动，面板标题和操作按钮保持可见。任务名称和任务标识按详情区宽度自动并排或换行。

选择目标数据库，打开「数据来源」。左侧「导入列表」支持搜索、新建和选择任务，右侧「导入详情」编辑脚本、运行计划和参数。点击列表标题旁的「外部连接」按钮，在弹窗中新增、编辑、测试连接或查看表结构；也可从任务详情直接新增连接。打开连接弹窗不会清除未保存的任务草稿。一个连接可供多个任务使用，一个任务可选择多个连接。SQLite 来源仅连接已有文件；被任务引用的连接不能删除。来源密码加密保存，编辑时留空保留。

在任务「脚本」页填写同步入口 `function main(params, context)`。通过 `sources.get("别名").query(sql, [值])` 读取来源，以 `db.target().query/update(sql, [值])` 读写当前目标库，SQL 使用 `?` 绑定参数。转换、关联、分页和新增／更新规则全部在 JS 中实现。目标表须预先存在；网络目标需先在动作配置中启用独立写入账号。SQLite 导入使用独立写连接，不依赖动作开关。

保存后先「回滚试运行」，确认日志和影响行数，再「立即运行」。试运行执行整个保存脚本并回滚，不保存正式进度；正式运行整次使用一个目标事务，成功才提交，错误、超时或停止则回滚。`context.log(message)` 记录日志，`context.checkpoint` 读取旧进度，`context.saveCheckpoint({...})` 在成功提交后保存新进度。进度与目标提交之间中断可能导致重放，脚本须能处理重复数据。每次查询最多 1000 行，超过则报错；大表需在 JS 中分批读取。脚本不支持 async、网络、文件或 npm。

「运行计划」支持仅手动、指定时间、固定间隔和每天运行。确认时区与预计时间，保存并开启自动运行后生效；同一任务不重叠执行，错过计划合并执行一次，失败不自动重试。默认执行时限 300 秒，可设为 1–3600 秒。调度由后台 admin-api 执行，关闭页面不影响运行。

在左侧独立菜单「数据运行记录」（位于「查询工作台」前）查看状态、日志、脚本版本、实际参数和进度，可按导入任务筛选，运行中可以停止。任务编辑页的「数据运行记录」按钮会打开当前任务的记录。试运行、失败和停止的影响行数不代表已提交；中断或结果未知时，先核对业务数据再决定重跑。此功能需要 `config.read` 和 `source.write`，允许读取来源并写入目标，不自动套用业务查询的行列策略和脱敏，须单独授权。

本地外部导入示例支持分地区销售、高校、渠道运营和证券四库，每库提供 Oracle、PostgreSQL 和 MySQL 三条真实数据库接入链路，使用符合各库业务场景的虚构事件导入独立接入表。按仓库 `examples/data-imports/README.md` 显式准备并安装后，可在「数据来源」体验每 2/3/5 分钟运行、回滚试运行、正式增量导入及失败回滚；在「数据运行记录」查看水位和日志，在「表数据」核对结果。三个来源各含 720 个预生成变更事件，消费完后正常空跑；新增接入表默认不向业务查询账号开放。

## 动作配置与脚本接口

新建动作的默认模板使用 `main(params, context)`：通过 `db.session()` 获取当前库连接，以 `conn.query` / `conn.queryOne` 读取、`conn.update` 写入，SQL 使用静态字符串和 `:name` 参数。查询不自动应用普通查询权限，脚本必须用 `context.userId` 检查记录归属；写入后核对 `result.rowsAffected`。公共库用 `exports.fn` 导出、`require("./库名称")` 引用。下面介绍仍兼容的 `run(args, ctx)` 模板，两种脚本接口不要混用。

在「动作配置」新建动作，填写名称、用途、参数及类型，再编写同步入口 `function run(args, ctx)`。例如把 id 定为整数、value 定为字符串，执行时就能从 `args.id` 和 `args.value` 取值。正式写入前需为当前库配置写连接并启用写入。

| 接口 | 用途 |
| --- | --- |
| `my.one` | 按业务身份及查询策略执行 SELECT，返回第一行，没有记录时返回 null。 |
| `my.all` | 按相同策略读取多行，返回行数组，遵守查询行数上限。 |
| `db.one` / `db.all` | 读取可信业务数据，绕过查询策略。分别返回第一行或 null、行数组。 |
| `db.exec` | 执行单条 INSERT、UPDATE 或 DELETE，返回受影响的行数。 |
| `deny(message)` | 拒绝操作并回滚整个动作，把原因返回给调用方。 |
| `ctx.userId` / `ctx.now` | 当前业务身份、本次操作固定的 UTC 时间。 |

SQL 接口使用反引号。把值写在 `${...}` 中，由系统绑定参数；表名和列名固定写在 SQL 里。下例假设 records 有 id、owner_id 和 value 三列，写入条件同时检查归属。把字段替换为当前库的实际字段后再试运行。

```js
function run(args, ctx) {
  const row = my.one`SELECT id FROM records WHERE id = ${args.id}`;
  if (!row) deny("记录不存在或无权查看");
  const count = db.exec`UPDATE records SET value = ${args.value}
    WHERE id = ${args.id} AND owner_id = ${ctx.userId}`;
  if (count !== 1) deny("记录已变化或无权修改");
  return { id: args.id, updated: count };
}
```

需要复用校验或业务逻辑时，在当前数据库创建公共函数库，用 `export function` 导出函数，在动作中用 `import { 函数名 } from "库名称"` 引入。

**AI 辅助**需要本库的 `config.read` 和 `action.write`。管理员在 admin-api 设置 `DATASCOPE_AI_ENDPOINT`、`DATASCOPE_AI_MODEL` 和提供商所需的 `DATASCOPE_AI_KEY` 后重启服务。端点可填以 `/v1` 结尾的基址或完整的 `/v1/chat/completions` 地址。若提供商返回 HTTP 404，核对端点和模型名称。若提示 `AI service returned an invalid response`，查看后面的具体原因：`finish_reason=length` 表示输出被截断，应提高提供商输出 token 上限或缩短需求；JSON 或字段类型错误需核对模型的 JSON 对象输出能力。仅兼容完整 JSON 外层代码块，以及已明确正常结束但省略 `[DONE]` 的流，不接受未完成的输出。后台逐段接收模型输出，默认等待首段或后续有效增量的空闲时限为 120 秒。完整建议校验后显示。参数或脚本校验失败时，助手会依据具体错误自动修正一次（上下文大小允许时），修正结果仍需通过全部校验。动作 SQL 使用统一解析器支持的语法子集，即使目标库是 PostgreSQL，也不能使用 `ILIKE`；不区分大小写的模式匹配可写为 `LOWER(name) LIKE LOWER(${args.pattern})`，模式值通过参数绑定，排序规则及 Unicode 大小写行为需在目标库验证。若提示“AI 建议未通过动作参数或脚本校验”，后面会列出具体原因（例如参数类型、模块语法、公共库导入或 SQL 模板错误）；将原因补充到需求中重新生成，或手工修正草稿，校验失败的建议不会应用。管理员可通过 `DATASCOPE_AI_TIMEOUT` 调整等待时间。若错误仍显示 30s，检查部署环境中的旧值，设置 `DATASCOPE_AI_TIMEOUT=120s` 后重启 admin-api；容器环境变量变化需重新创建容器。入口代理应覆盖完整生成及可能的一次自动修正，仓库 Docker 管理接口代理等待为 600 秒，外层网关也需相应配置。点击动作编辑器右上角的“AI 辅助”打开右侧对话抽屉，输入需求，例如“只允许修改 items 表中 owner_id 等于当前业务身份的记录，按 id 修改 name”。助手会使用当前草稿、库方言、已启用表的字段和公共库函数。可以多轮补充条件或回答澄清问题；每次携带最近六轮成功对话。抽屉显示请求状态、耗时、模型提供的思考摘要和正文。摘要是公开的方案说明，不展示内部推理；请求记录如实说明当前助手没有模型工具调用，也不执行动作 SQL。等待期间可以停止生成。对照当前草稿和建议，分别勾选参数、脚本，再点“应用到草稿”并确认。检查后点击“保存”。修改草稿或切换上下文会使旧建议失效，对话仅保留在当前页面内存中。模型离线时仍可手工编辑。

## MCP 配置与客户端接入

`query` 默认最多返回 200 行，全局上限为 1000 行，还受所涉及表的「返回行数上限」约束；多表查询取最小值。请求 `max_rows: 1000` 仍只返回 200 行时，先检查查询配置和 SQL 自带的 `LIMIT`。结果中的 `effective_max_rows` 是实际返回上限，`limit_source` 为 `default`（默认值）、`request`（请求值）、`hard_limit`（全局上限）或 `table_policy`（表策略）；表策略进一步降低上限时，`limiting_tables` 列出限制表。服务不会自动放宽已有策略。

只需汇总时，直接使用 `SUM`、`COUNT`、`MIN`、`MAX`、`AVG` 和 `GROUP BY`，例如 `SELECT natural_day, SUM(coop_fund) AS total FROM cashmgmt GROUP BY natural_day ORDER BY natural_day`（将表名、字段名替换为当前库已开放的名称）。这些聚合仍遵守行权限及字段限制。MySQL 与 OceanBase MySQL 模式支持这些普通聚合调用，不要求客户端设置 `IGNORE_SPACE`。

确需明细时，按稳定且唯一的键排序分页。例如 `SELECT id, amount FROM records WHERE id > :arg_after ORDER BY id`，传入 `parameters: {"arg_after": 0}` 和 `max_rows: 1000`；每页保存成功后，以最后一行的 id 作为下一页参数。根据实际表结构替换示例；复合键需要完整的排序和续页条件。`truncated: true` 表示本条 SQL 的结果超过返回上限。没有 SQL `LIMIT` 时可据此判断是否续页；SQL 自带 `LIMIT` 时，`truncated: false` 只表示该 SQL 的结果没有被额外截断，不能证明后面没有记录。多次请求不共享数据库快照，数据变动时需固定业务时间窗或使用业务快照。

托管 MCP 的 `query` / `raw_query` 复用同一配置版本的连接池和已校验规则，空闲一分钟释放，持续使用满五分钟后重新初始化。配置变化后的新请求重新初始化；每次调用仍校验当前身份及工具权限，不缓存查询结果。排查耗时时，在审计中按请求 ID 对照 `query.initialize`（详情 `cache_hit` 标明是否命中复用）、`sql.rewrite`、`sql.guard`、`sql.execute` 和 `mcp.request` 的起止时间；这些事件可能嵌套，不能直接相加。

HTTP MCP 在单次请求内复用已校验的配置快照与认证策略，避免同一数据源反复读取全部 YAML。以数据库 ID 为路径的端点直接定位目标库；自定义路径仍校验配置中的实际路径，不会把旧 ID 自动当作别名。可变快照不跨请求共享：已开始的请求使用本次读取的配置，新请求重新校验配置文件内容、令牌和权限，保存后的停用、权限撤销及路径变更在后续请求生效；请求内发生配置写入时停用快照复用。该机制不缓存业务查询结果，也不将 HTTP 快照保留到长连接的下一次调用。

平台管理连接器使用 `/mcp/admin`，与各数据库的业务 MCP 分开。管理 MCP 已支持 SQLite DDL 对象查询、预览、执行与执行历史；需开启本库 DDL 管理并满足权限。先预览取得 plan_id，再执行；结果不确定时先查询执行记录。普通业务 MCP 不提供 DDL。系统管理员还可通过管理 MCP 测试并保存网络库的候选连接，或移除数据源登记；移除保留业务文件，连接编辑不允许更换目标数据库。

动作 AI 助手按当前草稿的入口选择契约：main 使用 db.session() 与 CommonJS，旧 run 保留标签模板契约，不自动迁移。两种契约均拒绝相对已保存动作新增或改写绕过查询策略的 SELECT；需要新增读取时请手工编写并审核权限。

在「MCP 配置」为当前库开放所需工具，保存配置。动作、知识和视图各自使用总开关，位于对应配置页的列表表头，也可在 MCP 配置页操作；两处修改同一状态并立即保存，侧边栏仅在总开关打开时显示「已打开」，关闭时不显示状态文字。有未保存草稿时先保存，再操作总开关。动作组的列表、参数说明、执行工具一起启停；网络库首次打开需配置独立写入账号。知识组的检索和正文读取一起启停。视图组统一控制已发布 HTML 的发现与读取，关闭后停止默认展示推荐，SQL 查询仍可用。开关不修改条目的发布状态，业务调用仍需要全局 MCP 开关及账号能力。动作需 `action.write`；知识需 `knowledge.write` 或 `mcp.write`；视图需 `view.write` 或 `mcp.write`。普通查询工具仍可单独选择，MCP 地址和工具选择通过保存按钮提交。按页面提供的连接信息配置客户端，并使用该库匹配的业务认证方式。OAuth 接入时，在客户端选择 `mcp`，由授权流程跳转登录；本库账号使用本库业务账号提供方，企业 SSO 使用企业 SSO 提供方。「数据库配置 → 业务认证」卡片右上角的「发现地址」可打开已保存生效的 OAuth 资源元数据，悬停查看完整 URL；未保存的认证草稿不会改变该链接。先列出工具，再用一个简单请求检查身份、权限和返回内容。

客户端支持导入连接器时，可在启用 MCP 并保存后点击「下载连接器 ZIP」，将文件导入客户端，再按当前库的认证方式登录。

例如，启用表目录、表结构和权限查询后，依次调用 `list_tables`、`describe_table` 和 `query`。业务动作分别使用 `list_actions`、`describe_action` 和 `invoke_action`。工具未出现时，检查工具开关、资源是否已发布，以及业务账号在该库的能力。

## 操作日志与排查


在「操作日志」选择目标数据库或平台日志，按请求 ID、操作用户、业务身份或工具定位记录。排查一次调用时，先核对数据库和身份，再看工具、策略版本及执行结果。

日志列表的「耗时」以毫秒显示事件结束时间与开始时间之差，最多保留三位小数；正耗时不足 0.001 ms 时显示 `<0.001 ms`。展开记录可查看原始开始时间、结束时间及耗时；历史日志只要有完整起止时间即可显示。缺少结束时间、时间无效或结束早于开始时显示「—」，不将其视为零耗时。`sql.execute` 和 `action.sql` 的耗时包含各自事件范围内的 SQL 准备、连接或事务获取、执行及结果读取等步骤，并非数据库内部的纯 SQL 执行时间；嵌套事件不能直接相加。

在「高级筛选」设置「最小耗时（ms）」（例如 `1000`，包含恰好达到阈值的记录），并选择「耗时从高到低」或「耗时从低到高」；默认「最新优先」。筛选和排序在后端对全部匹配日志生效后再分页，耗时未知的记录不进入耗时筛选，在耗时排序中排在末尾。筛选作用于所有事件；只看慢 SQL 时同时选择操作类型 `sql.execute` 或 `action.sql`。筛选与排序随页面地址保留，重置后恢复默认。

「返回 / 影响行数」区分查询返回行数和写 SQL 影响行数；失败、未完成及非 SQL 事件显示「—」。旧的动作日志没有行数类型时只标为「行数」，不猜测读写类型。「结果集」对成功且已知为查询的记录显示「完整」或「已截断」；截断表示达到返回上限，不代表总匹配行数。影响行数仅表示该语句的执行结果，不代表事务已提交，动作试运行或后续失败仍可能回滚。

管理 API 的 `get_audit_page` / `search_audit_events` 及管理 MCP 的 audit `page` / `search` 支持 `min_duration_ms`（非负毫秒数，可含小数）和 `sort`（`time_desc`、`duration_desc`、`duration_asc`）。新 SQL 日志的 `rows_kind` 为 `returned` 或 `affected`，旧记录可缺省；`rows` 和 `truncated` 保持原含义。

排查 HTTP MCP 的 `ping` 或公共路径延迟时，由运维在 MCP 进程的环境中设置 `DATASCOPE_MCP_TIMING=1` 并重启服务；默认关闭，排查完成后移除变量并重启。在服务进程日志中搜索 `mcp.request.timing`，按 `request_id` 与操作日志关联。每个 POST 请求输出一条汇总，包含 `method`、`tool`、`query_cache_hit`、HTTP `status`、`total_ms`、`first_write_ms`、`stages_ms` 和 `stage_counts`，不记录请求头、令牌、SQL 或业务结果。`first_write_ms` 是应用首次写响应头的时间，不是客户端首字节时间；未写响应时为 null。认证前失败且未解析方法的请求，`method` 可能为空。

新请求首次读取逐库配置时，在发布锁内校验完整配置文件内容摘要；内容不变则复用进程内已解析的配置，内容变化则重新解析并校验，不依赖 TTL。管理 API 发布、其他进程发布及 YAML 内容修改在下一次请求读取时生效；当前请求继续使用自己的快照。解析失败或文件读取失败不会回退到旧配置。每个调用仍获得独立深拷贝，写操作不使用该解析缓存。此优化减少 YAML 解析和 JSON 复制，仍需逐请求读取文件校验内容。

`config_cache_check` 记录文件内容校验耗时（缓存未命中时在解析前后各校验一次）；`config_cache_hit` 的调用次数为 1 表示本请求复用了已解析配置，此时通常没有 `read_state`。它与查询服务缓存 `query_cache_hit` 是两个不同的缓存。

`route_lookup` 表示端点配置查找，`resolve_auth` 表示认证策略解析，`handler_build` 表示协议处理器构建，`verify_token` 表示令牌校验，`middleware_get` 表示协议中间件再次读取配置，`business_get` 表示业务权限中间件读取配置；`config_state`、`read_state`、`lock_wait` 和 `lock_hold` 分别表示配置操作、配置文件读取、文件锁等待和持锁耗时。OneID 另记录 `jwks_lock_wait`，公钥缓存未命中时记录 `jwks_fetch`。阶段单位均为毫秒，同名阶段累计，调用次数见 `stage_counts`；阶段会嵌套，不能直接相加。对照串行和 4 并发的 `ping`：若 `lock_wait` 明显增加，优先检查配置锁竞争；若应用总耗时很低而客户端耗时高，对照应用内部端口与公网入口定位网关或网络等待。计时只用于诊断，不改变鉴权、缓存或锁策略。

工具初始化另记录 `query_initialize`，包含查询服务缓存获取或新建。`query_cache_hit=true` 表示复用查询服务，false 表示未复用，null（文本日志可能显示 `<nil>`）表示本次请求未执行该初始化步骤；`tool` 用于区分 `query`、`list_tables`、`describe_table` 等。新建时的 `store_open` 包含凭据读取、连接打开及存储配置，`service_initialize` 表示查询规则和服务初始化。网络数据库的 `connection_open` 进一步包含 `connection_ping`（连通性检查）、`connection_readonly`（建立并回滚只读事务）和 `connection_table_names`（连接初始化时读取表目录）；这些子阶段不能与父阶段重复相加，失败时仅记录实际执行到的阶段。

`query`、`raw_query`、`list_tables` 和 `describe_table` 共用按配置快照隔离的服务缓存，空闲 1 分钟或创建满 5 分钟后重建；配置变更后下一次调用使用新服务。认证与工具权限仍逐次检查，元数据结果仍逐次读取，不缓存工具响应。网络数据库初始化通过零行只读查询校验实际读取权限和字段名，记录为 `validation_columns`，不再为字段校验读取完整索引、外键和注释；SQLite 保留原结构校验。

`metadata_tables`、`metadata_describe` 分别记录表清单和表结构读取，可能同时出现在服务初始化与工具执行中，需结合调用次数和父阶段判断。`query_execute` 记录数据库执行路径，包括连接/事务获取、查询和结果读取等，并非数据库纯 SQL 执行时间。排查首次查询或元数据接口偏慢时，先比较 `query_initialize`，再看 `store_open`、`connection_open`、`service_initialize` 与元数据读取；缓存命中的查询通常不会出现新建阶段。`query_release` 记录服务租约释放或连接关闭耗时。

- **找不到菜单**：核对顶部数据库和平台账号的库级授权。
- **查询返回空结果**：核对参数值、业务身份和行过滤条件；在查询工作台查看改写后的 SQL。
- **试运行成功但业务数据未变化**：试运行会回滚。到真实业务调用页查看正式请求及确认状态。
