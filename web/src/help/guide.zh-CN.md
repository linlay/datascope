# DataScope 用户手册

## 从哪里开始

登录控制台后，先在左上角选择数据库。左侧菜单随当前库和平台账号的授权变化。要查业务数据，进入「查询工作台」；要执行已经定义好的业务操作，进入「动作工作台」。

首次接入一个库时，管理员可按以下顺序验收：

1. 在「增加数据库」登记数据源并测试连接。
2. 在「查询配置」选一张表，开放必要的字段，并配置可见行。
3. 在「查询工作台」用一位业务用户的身份查询，核对可见记录和字段。
4. 在「MCP 配置」启用所需工具，再用目标业务账号连接并验证。

配置表单中的常规输入框、下拉框和开关统一采用左标签、右组件布局，标签正文按 5 个汉字宽度预留，冒号、必填标记和 tips 图标单独占位，长标签自动换行，适用于数据库连接、业务认证、账号权限、动作、知识、视图、数据来源和相关设置弹框。长文本、SQL、脚本及参数表保留独立区域；窄屏自动上下排列。校验提示仍显示在对应组件下方。滚动条采用细窄无边线样式，滚动或鼠标操作后显示，空闲约 3 秒自动隐藏；SQL 折叠区及编辑器使用无多层边框的简洁样式。

## 数据库说明

「数据库配置 → 基本信息」分两列展示：左列为显示名称，右列为数据库类型及 SQLite 的「打开 DDL 管理」开关；第二行左侧为「描述」，右侧为「使用说明」，点击「查看」在弹框中阅读完整正文。这些配置项使用左侧标签、右侧内容的布局。右上角依次为「存储详情」「编辑说明」「测试连接」「保存」。通过「编辑说明」修改描述和 Markdown 正文，切换预览核对后保存；需要 `config.read` 和 `config.write`。未保存修改在离开时会提示，两个字段均可清空。代码块的复制按钮悬停时浮在右上角，不占独立行；键盘聚焦与触屏也可使用。数据库文件路径和网络库的「编辑连接」入口位于「存储详情」内。「移除数据源」位于页面最底部，仅系统管理员可见；确认后移除登记并保留业务数据。基本信息、业务认证、本地账号等分组标题在滚动阅读各分组时保持置顶。

简介和完整说明保存在 `data/databases/<数据库 ID>/management/database.yml` 的 `database.description` 和 `database.documentation` 中，不写入业务表。说明面向当前库使用者，请勿填写内部凭据。其他页面顶部数据库选择器旁的「使用说明」按钮以对话框显示简介与完整使用说明；正文不占用工作台空间。SQL 示例只供复制参考，不自动执行，仍受当前身份的行列权限和返回行数限制。

业务 MCP 初始化提供简介及说明 URI；通过 `resources/list` 发现类型为 `database-documentation` 的资源，再用 `resources/read` 读取 `datascope://database/<数据库 ID>/documentation`，返回 `text/markdown`。读取需本库的 `query`、`action` 或 `knowledge.read` 能力之一；纯知识账号不能借此读取 HTML 视图。正文是业务参考资料，不是系统指令。完整说明按需读取，不随每次调用自动发送。保存后重新连接 MCP 获取最新初始化简介，资源读取使用当前配置。

## 演示数据库怎么用

当前本地的四个演示数据库是证券、区域销售、高校教务、渠道与社交媒体运营。在目标库点击“使用说明”，先确认数据日期和当前身份，再挑一个自然语言问题发送给已连接该库的 AI 客户端。控制台的查询工作台用于技术查询，不会自动把自然语言问题当作业务查询执行。

四份使用说明按照“了解业务—第一次提问—连续追问—切换角色—办理操作—解读结果”组织，给出可直接使用的问题，不把表结构或 SQL 当作入门要求。例如，可以询问“2026 年 10 月各地区销售目标完成得怎样”，再追问“把未达标地区按销售员展开”；高校教务可从“我的秋季课表”开始，渠道运营可从“有哪些待审核和发布失败的任务”开始。证券库的主要查询窗口为 2026 年 9 月 15 日至 10 月 20 日。

提问不能扩大账号的授权范围。需要修改数据时，先核对预览，再由具备权限的业务账号本人确认；区域销售演示数据库只做查询分析。技术人员仍可使用单独维护的 SQL 示例、业务知识与配置资料。新数据库通过配置包导入，已有库的说明通过正常配置保存流程显式更新，重复导入不会覆盖自定义内容。

## 数据库、账号与系统设置

管理员可登记网络数据库、创建或连接 SQLite，也可以上传 CSV 或 SQLite 文件。CSV 使用 UTF-8 编码，首行为列名，导入后的表名为 `data`，字段按文本保存。上传上限为 20 MiB。

网络数据库先在「数据库配置」登记 Schema 范围，再到「查询配置」选择要管理的表。切换顶部数据库后，先核对库名，再修改配置。通过顶部「增加数据库」选择「全新配置」手动填写，或选择「从已有数据库克隆」，选来源库并填写新库名称及连接。来源连接会预填供修改，密码需重新输入，SQLite 需填写目标文件路径；也可上传文件作为新库。克隆先创建独立的新库，再预览并确认复制表与字段配置、查询权限、Actions、知识、视图等所选范围，认证配置默认不选。网络库会先登记来源库已配置的表，目标必须存在兼容结构。来源库保持不变，不复制业务数据、密码、账号或授权；新库的 MCP 和写入默认关闭。克隆失败可在同一新库重试，或选择「保留新库，稍后配置」，不会再次创建。

系统管理员可在「数据库配置 → 基本信息 → 存储详情 → 编辑连接」维护网络数据库的地址、端口、只读账号、密码和 TLS。密码留空保留原密码，新密码加密保存。点击「测试连接」检查草稿，再点击「校验并保存」；保存时会重新测试并检查已登记字段是否存在且类型、非空和主键属性兼容，失败时保留原配置及密码。已有动作写连接同步地址、端口和 TLS，保留独立的写账号和密码，并一并测试。修改期间若其他窗口保存了配置，请刷新后重试。成功保存保留数据源 ID、权限及业务配置，并记录审计日志。此入口仅用于同一业务库的维护，结构校验不能证明业务数据相同；切换实际业务库或数据库类型请新建数据源。SQLite 不提供此入口，库名及 Schema 范围不在此弹窗修改。

平台账号用于登录控制台，数据库授权决定可以看到哪些工作台、谁能编辑或试运行。业务身份用于计算数据可见范围和执行正式动作。在当前库配置业务认证、账号及能力；菜单缺失时，请管理员检查该平台账号在此库的授权。OneID 接入说明在「认证服务」选择框旁的帮助按钮中查看；使用全局提供方时，帮助按钮位于「认证提供方」旁。右上角「系统设置」可切换语言、外观，并按权限管理平台设置。

## 查询配置、查询工作台与表数据

查询配置、动作配置、知识配置和视图配置占满可用工作区，左右列表及编辑内容各自内部滚动，面板标题和操作按钮保持可见。查询配置的数据表列表最大宽度为 420px，可显示带 schema 的表名；宽屏剩余空间用于右侧详情。

在「查询配置」选择表，确定开放字段、行过滤条件和返回行数上限。行过滤入口始终显示：SQL 为空时标题为「行级过滤」，已有 SQL 时为「行过滤 SQL」。展开后可直接添加 SQL，填写内容会自动选择「使用 SQL 过滤」，清空则切换为「无需行权限过滤」。「前置查询准入 SQL」可用于设置查询前必须满足的条件及拒绝提示，留空则不进行这项检查。两处 SQL 无论是否已有内容，默认均折叠，标题旁以「已配置 SQL」或「未配置 SQL」标记是否已有内容，点击标题可展开查看和编辑，再次点击收起；折叠不影响策略生效或保存。用字段说明记录业务含义，对敏感字段配置脱敏。保存后用业务身份测试一条应可见的记录，再测试一条应隐藏的记录。

在「查询工作台」输入只读 SELECT，选择身份并执行。例如，库中有 customers 表时，可输入 `SELECT customer_no FROM customers WHERE customer_no = :number`，并在参数区填写 `{"number":"C001"}`。检查返回结果和改写后的 SQL，确认权限条件生效。具备全量查询权限的账号还可对照原始结果。

要直接核对表中的记录，在「表数据」选择表并筛选记录。此入口需要全量查询权限；验证某个业务用户实际能看到什么，请在查询工作台使用该身份。

## 数据来源、导入脚本与定时任务

选择目标数据库，打开「数据来源」。左侧「导入列表」支持搜索、新建和选择任务，右侧「导入详情」编辑脚本、运行计划和参数。点击列表标题旁的「外部连接」按钮，在弹窗中新增、编辑、测试连接或查看表结构；也可从任务详情直接新增连接。打开连接弹窗不会清除未保存的任务草稿。一个连接可供多个任务使用，一个任务可选择多个连接。SQLite 来源仅连接已有文件；被任务引用的连接不能删除。来源密码加密保存，编辑时留空保留。

在任务「脚本」页填写同步入口 `function main(params, context)`。通过 `sources.get("别名").query(sql, [值])` 读取来源，以 `db.target().query/update(sql, [值])` 读写当前目标库，SQL 使用 `?` 绑定参数。转换、关联、分页和新增／更新规则全部在 JS 中实现。目标表须预先存在；网络目标需先在动作配置中启用独立写入账号。SQLite 导入使用独立写连接，不依赖动作开关。

保存后先「回滚试运行」，确认日志和影响行数，再「立即运行」。试运行执行整个保存脚本并回滚，不保存正式进度；正式运行整次使用一个目标事务，成功才提交，错误、超时或停止则回滚。`context.log(message)` 记录日志，`context.checkpoint` 读取旧进度，`context.saveCheckpoint({...})` 在成功提交后保存新进度。进度与目标提交之间中断可能导致重放，脚本须能处理重复数据。每次查询最多 1000 行，超过则报错；大表需在 JS 中分批读取。脚本不支持 async、网络、文件或 npm。

「运行计划」支持仅手动、指定时间、固定间隔和每天运行。确认时区与预计时间，保存并开启自动运行后生效；同一任务不重叠执行，错过计划合并执行一次，失败不自动重试。默认执行时限 300 秒，可设为 1–3600 秒。调度由后台 admin-api 执行，关闭页面不影响运行。

在左侧独立菜单「数据运行记录」（位于「查询工作台」前）查看状态、日志、脚本版本、实际参数和进度，可按导入任务筛选，运行中可以停止。任务编辑页的「数据运行记录」按钮会打开当前任务的记录。试运行、失败和停止的影响行数不代表已提交；中断或结果未知时，先核对业务数据再决定重跑。此功能需要 `config.read` 和 `source.write`，允许读取来源并写入目标，不自动套用业务查询的行列策略和脱敏，须单独授权。

## 动作配置与脚本接口

新建动作的默认模板使用 `main(params, context)`：通过 `db.session()` 获取当前库连接，以 `conn.query` / `conn.queryOne` 读取、`conn.update` 写入，SQL 使用静态字符串和 `:name` 参数。查询不自动应用普通查询权限，脚本必须用 `context.userId` 检查记录归属；写入后核对 `result.rowsAffected`。公共库用 `exports.fn` 导出、`require("./库名称")` 引用。下面介绍仍兼容的 `run(args, ctx)` 模板，两种脚本接口不要混用。

在「动作配置」新建动作，填写名称、用途、参数及类型，再编写同步入口 `function run(args, ctx)`。例如把 id 定为整数、value 定为字符串，执行时就能从 `args.id` 和 `args.value` 取值。正式写入前需为当前库配置写连接并启用写入。

| 接口 | 用途 |
| --- | --- |
| `my.one` | 按业务身份及查询策略执行 SELECT，返回第一行，没有记录时返回 null。 |
| `my.all` | 按相同策略读取多行，返回行数组，遵守查询行数上限。 |
| `db.one` / `db.all` | 读取可信业务数据，绕过查询策略。分别返回第一行或 null、行数组。 |
| `db.exec` | 执行单条 INSERT、UPDATE 或 DELETE，返回受影响的行数。 |
| `deny(message)` | 拒绝操作并回滚整个动作，把原因返回给调用方。 |
| `ctx.userId` / `ctx.now` | 当前业务身份、本次操作固定的 UTC 时间。 |

SQL 接口使用反引号。把值写在 `${...}` 中，由系统绑定参数；表名和列名固定写在 SQL 里。下例假设 records 有 id、owner_id 和 value 三列，写入条件同时检查归属。把字段替换为当前库的实际字段后再试运行。

```js
function run(args, ctx) {
  const row = my.one`SELECT id FROM records WHERE id = ${args.id}`;
  if (!row) deny("记录不存在或无权查看");
  const count = db.exec`UPDATE records SET value = ${args.value}
    WHERE id = ${args.id} AND owner_id = ${ctx.userId}`;
  if (count !== 1) deny("记录已变化或无权修改");
  return { id: args.id, updated: count };
}
```

需要复用校验或业务逻辑时，在当前数据库创建公共函数库，用 `export function` 导出函数，在动作中用 `import { 函数名 } from "库名称"` 引入。

**AI 辅助**需要本库的 `config.read` 和 `action.write`。管理员在 admin-api 设置 `DATASCOPE_AI_ENDPOINT`、`DATASCOPE_AI_MODEL` 和提供商所需的 `DATASCOPE_AI_KEY` 后重启服务。端点可填以 `/v1` 结尾的基址或完整的 `/v1/chat/completions` 地址。若提供商返回 HTTP 404，核对端点和模型名称。若提示 `AI service returned an invalid response`，查看后面的具体原因：`finish_reason=length` 表示输出被截断，应提高提供商输出 token 上限或缩短需求；JSON 或字段类型错误需核对模型的 JSON 对象输出能力。仅兼容完整 JSON 外层代码块，以及已明确正常结束但省略 `[DONE]` 的流，不接受未完成的输出。后台逐段接收模型输出，默认等待首段或后续有效增量的空闲时限为 120 秒。完整建议校验后显示。参数或脚本校验失败时，助手会依据具体错误自动修正一次（上下文大小允许时），修正结果仍需通过全部校验。动作 SQL 使用统一解析器支持的语法子集，即使目标库是 PostgreSQL，也不能使用 `ILIKE`；不区分大小写的模式匹配可写为 `LOWER(name) LIKE LOWER(${args.pattern})`，模式值通过参数绑定，排序规则及 Unicode 大小写行为需在目标库验证。若提示“AI 建议未通过动作参数或脚本校验”，后面会列出具体原因（例如参数类型、模块语法、公共库导入或 SQL 模板错误）；将原因补充到需求中重新生成，或手工修正草稿，校验失败的建议不会应用。管理员可通过 `DATASCOPE_AI_TIMEOUT` 调整等待时间。若错误仍显示 30s，检查部署环境中的旧值，设置 `DATASCOPE_AI_TIMEOUT=120s` 后重启 admin-api；容器环境变量变化需重新创建容器。入口代理应覆盖完整生成及可能的一次自动修正，仓库 Docker 管理接口代理等待为 600 秒，外层网关也需相应配置。点击动作编辑器右上角的“AI 辅助”打开右侧对话抽屉，输入需求，例如“只允许修改 items 表中 owner_id 等于当前业务身份的记录，按 id 修改 name”。助手会使用当前草稿、库方言、已启用表的字段和公共库函数。可以多轮补充条件或回答澄清问题；每次携带最近六轮成功对话。抽屉显示请求状态、耗时、模型提供的思考摘要和正文。摘要是公开的方案说明，不展示内部推理；请求记录如实说明当前助手没有模型工具调用，也不执行动作 SQL。等待期间可以停止生成。对照当前草稿和建议，分别勾选参数、脚本，再点“应用到草稿”并确认。检查后点击“保存”。修改草稿或切换上下文会使旧建议失效，对话仅保留在当前页面内存中。模型离线时仍可手工编辑。

## 动作工作台、试运行与正式执行

1. 在「动作工作台」获取动作列表，选择动作，查看必填参数、类型和人工确认要求。
2. 在试运行页签填写参数 JSON 和业务身份。查看返回值与 SQL 写入计划；此模式始终回滚。修改参数后使用新请求重新预览。
3. 准备正式执行时，先确认动作已发布、业务账号有动作能力，并已开放相应 MCP 工具。在「真实业务调用」中用本人业务身份认证后提交。需要人工确认时，打开返回的确认链接，核对预览后执行。
4. 正式请求中断时，保留 request_id，先查询原请求结果。若状态为 unknown，核对操作日志及业务记录，再决定是否重试。

在“试运行（回滚）”中，有上述编辑权限及 `impersonate` 的用户可以点“AI 生成测试参数”，检查并采用测试用例，编辑参数与预期结果。手动选择业务身份并执行。例如，对同一个 id 分别使用该记录的管理者和其他身份，核对写入计划、影响行数和拒绝原因。在“AI 解释试运行”中，模型只收到参数类型、诊断分类或返回类型和写入行数。明确的脚本缺陷可点“带回动作草稿”，按修复意见重新生成并审核。上下文变化会丢弃旧建议。

## 知识配置与知识工作台

在「知识配置」为当前数据库编写业务术语、指标口径或查询示例。给条目起一个用户容易搜索的名字，保存正文并检查发布状态。

在「知识工作台」列出条目，再用业务关键词搜索。打开命中条目，对照正文预览和返回 JSON。调用方搜不到时，核对当前数据库、条目发布状态和账号能力。

## 视图配置与视图工作台

在「视图配置」点击「预览 HTML」会打开独立预览弹框，内容仅在预览区域内滚动，关闭后回到原编辑位置。也可从通用模板创建 HTML 视图，填写标识、名称和 HTML，保存草稿。在「视图工作台」先用模拟数据预览布局，再用身份预览检查实际返回的字段、可见记录和空结果。发布后，可在「真实业务预览」用本人业务身份载入视图；其中的正式动作会走真实执行流程。要让查询默认推荐此视图，在「视图配置」点击「MCP 展示推荐」，在对话框中选中它。这是可选的客户端展示推荐，客户端决定是否使用；不改变查询数据，也不影响 SQL 工作台。

如果模拟预览正常、身份预览为空，请先在同一数据库用同一身份检查底层查询，再核对视图读取的字段名。

## MCP 配置与客户端接入

平台管理连接器使用 `/mcp/admin`，与各数据库的业务 MCP 分开。管理 MCP 已支持 SQLite DDL 对象查询、预览、执行与执行历史；需开启本库 DDL 管理并满足权限。先预览取得 plan_id，再执行；结果不确定时先查询执行记录。普通业务 MCP 不提供 DDL。系统管理员还可通过管理 MCP 测试并保存网络库的候选连接，或移除数据源登记；移除保留业务文件，连接编辑不允许更换目标数据库。

动作 AI 助手按当前草稿的入口选择契约：main 使用 db.session() 与 CommonJS，旧 run 保留标签模板契约，不自动迁移。两种契约均拒绝相对已保存动作新增或改写绕过查询策略的 SELECT；需要新增读取时请手工编写并审核权限。

在「MCP 配置」为当前库开放所需工具，保存配置。动作、知识和视图各自使用总开关，位于对应配置页的列表表头，也可在 MCP 配置页操作；两处修改同一状态并立即保存，侧边栏显示「打开 / 已打开」。有未保存草稿时先保存，再操作总开关。动作组的列表、参数说明、执行工具一起启停；网络库首次打开需配置独立写入账号。知识组的检索和正文读取一起启停。视图组统一控制已发布 HTML 的发现与读取，关闭后停止默认展示推荐，SQL 查询仍可用。开关不修改条目的发布状态，业务调用仍需要全局 MCP 开关及账号能力。动作需 `action.write`；知识需 `knowledge.write` 或 `mcp.write`；视图需 `view.write` 或 `mcp.write`。普通查询工具仍可单独选择，MCP 地址和工具选择通过保存按钮提交。按页面提供的连接信息配置客户端，并使用该库匹配的业务认证方式。OAuth 接入时，在客户端选择 `mcp`，由授权流程跳转登录；本库账号使用本库业务账号提供方，企业 SSO 使用企业 SSO 提供方。「数据库配置 → 业务认证」卡片右上角的「发现地址」可打开已保存生效的 OAuth 资源元数据，悬停查看完整 URL；未保存的认证草稿不会改变该链接。先列出工具，再用一个简单请求检查身份、权限和返回内容。

客户端支持导入连接器时，可在启用 MCP 并保存后点击「下载连接器 ZIP」，将文件导入客户端，再按当前库的认证方式登录。

例如，启用表目录、表结构和权限查询后，依次调用 `list_tables`、`describe_table` 和 `query`。业务动作分别使用 `list_actions`、`describe_action` 和 `invoke_action`。工具未出现时，检查工具开关、资源是否已发布，以及业务账号在该库的能力。

## 本地示例数据维护

以下命令在仓库根目录运行，仅操作指定的本地示例库，不修改认证、业务账号或权限配置；运行时避免同时执行业务写入。

证券库可执行 `python3 examples/securities/compact.py --db data/securities_demo.sqlite3 --keep-days 20`：先将完整库备份到 `data/backups/`，再保留最近 20 个交易日的持仓和资金日结快照并回收空间，默认保留全部交易流水。若要进一步缩减，执行 `python3 examples/securities/compact.py --db data/securities_demo.sqlite3 --keep-days 20 --trim-ledgers --preserve-account 880000001186`，同步裁剪窗口前的委托、成交和资金流水，保留指定账户的完整流水供 Action 回归。本地实测约 47.32 MiB（49.62 MB），窗口为 2026-09-15 至 2026-10-20。客户、账户、授权、行情和原有索引保留；保留日期的记录与日初余额不重新计算。`--preserve-account` 可重复指定，必须配合 `--trim-ledgers`；`--backup-dir` 指定备份目录，`--keep-days` 必须为正整数，窗口以库内最新快照为准。交易裁剪提交前检查外键及 15 项账务一致性，失败回滚；提交后整理失败仍可查备份恢复。由于回归账户额外保留历史，成交总额与排行必须限定同一日期窗口，SQL 示例已按该窗口更新。更早完整历史应查备份，缺失记录不能视为零。全历史统计或压测使用完整备份；恢复前停止访问该库的服务。

`make init-shop` 创建 200 个客户、100 件商品及 3,000 张订单的商店库，订单覆盖 2026 年 5 月至 10 月。已有微型库执行 `python3 examples/shop/generate.py --db data/shop_demo.sqlite3 --expand-existing`，先备份再补齐数据，保留已有记录。默认创建命令拒绝覆盖已有文件。

商店保留四种订单状态、无订单客户、无销量和零库存商品。销售额以已付款及已发货订单的 `quantity*unit_price_cents` 计算，单位为分。SHOP001 只看业务身份 1 的客户和订单；商品目录全员可读，成本字段隐藏。`examples/shop/sql-examples.yml` 提供月度销售、客户与商品排行、状态分布及空数据查询示例；新库通过配置包导入，已有库可复制到查询工作台执行，重复导入不会覆盖自定义配置。

高校教务示例使用 `make init-academic` 创建 `data/academic_demo.sqlite3`，约 14 MiB，包含 1,000 名学生、80 名教师及两个学期的课表、选课、成绩、考勤与考试。需要接入平台时，设置 `DATASCOPE_EXAMPLE_PASSWORD`（至少 12 字符），再执行 `make check-example EXAMPLE=academic`、`make import-example EXAMPLE=academic`。五类账号为 ACA001（教务管理员）、ACA002（学院教务员）、T1001（教师）、F2001（辅导员）、202301001（学生）。已有库和账号不会被重复导入覆盖。

在查询工作台选择教务库和业务身份，使用 SQL 示例检查可见课表、成绩与考勤。学生只能查看本人已发布的成绩；教师只看本人授课教学班；辅导员范围随任职日期变化。pending 分数为空，不能按 0 计入平均分；通过率只统计三项考核均已发布的完整课程。查询中的选课人数只代表当前身份可见记录，真实容量由选课 Action 独立检查。在动作工作台试运行选课、退课、录入成绩、发布成绩或调整教室，再由相应业务账号本人确认。默认快照为 2026-11-13，已过选退课期限，选退课应拒绝；评分仅限授课教师，发布仅限主讲，发布后锁定。成功选退课的自动验收使用 2026-09-10 快照和同日可信执行时间。姓名、联系方式及校历全部虚构，详细口径见 `examples/academic/guide.md`。

渠道与社交媒体运营示例使用 `make init-channel-operations` 创建 `data/channel_operations_demo.sqlite3`，约 22 MiB，包含 4 个模拟平台、12 个账号、600 个选题及 1,600 次发布任务。设置 `DATASCOPE_EXAMPLE_PASSWORD` 后执行 `make check-example EXAMPLE=channel-operations`、`make import-example EXAMPLE=channel-operations`。OPS001–OPS007 分别提供管理员、负责人、分析员、编辑、运营、外部协作和另一团队负责人身份。服务不会自动安装示例，已有配置和账号不会被重复导入覆盖。

在查询工作台检查账号授权、内容分工及十个 SQL 示例。跨平台阅读播放不等于去重触达；累计快照和关注存量不能跨日求和；缺失指标为 NULL，不能按 0 处理。自然与付费无法拆分时单列未知，平台报告转化和站内七天最后点击归因分别统计，未知归因不强行分配。推广成本仅管理员、负责人和分析员可见，外部协作方只看分配内容。在动作工作台试运行提交、审核、排期、记录模拟发布结果、评论处置或编辑分工，再由对应业务账号本人确认。选题可见不授予账号运营权限，READ 授权不能操作，未来排期不能提前记录成功。所有发布和回复只更改本地演示数据，详细口径见 `examples/channel-operations/guide.md`。

## 操作日志与排查

在「操作日志」选择目标数据库或平台日志，按请求 ID、操作用户、业务身份或工具定位记录。排查一次调用时，先核对数据库和身份，再看工具、策略版本及执行结果。

- **找不到菜单**：核对顶部数据库和平台账号的库级授权。
- **查询返回空结果**：核对参数值、业务身份和行过滤条件；在查询工作台查看改写后的 SQL。
- **试运行成功但业务数据未变化**：试运行会回滚。到真实业务调用页查看正式请求及确认状态。
