# 多平台渠道运营业务与统计口径

本例为虚构的「原野生活」「山岚营地」双品牌运营，覆盖两个内部团队及一个外部创作团队。四个平台均为模拟平台，接口、指标及审核流程不代表任何真实服务。默认快照为 2026-11-13，包含 2026 年 5–10 月的历史运营与 11 月的近期及未来排期。全部人名、评论、素材及转化事件均为合成数据，无真实用户身份。

## 内容和发布流程

`content_items` 表示选题与简报，按编辑和协作方分工；`content_versions` 表示针对某个平台的标题、正文、素材及修订版本。一个选题可有四种平台改编，一个版本可以通过不同账号发布。`publications` 是具体账号上的一次发布任务，版本和账号组合唯一。修改已发布文案应建立新修订版本，本例不提供覆盖历史版本的操作。

内容状态为 draft → submitted → approved/rejected。只有负责编辑或被分配的协作方可以提交，内部负责人审核，作者不能自审；被拒稿的版本可以补充新版本后重新提交。发布任务为 draft → scheduled → published/failed → removed（下架为历史样例，不提供任意回退）。发布状态变更必须追加 `publication_events`，失败记录保留原因。计划发布时间与实际发布时间分开，未来排期事件的办理时间是当前日期，而非未来的计划时间。

账号 OPERATE 授权、有效日期及账号 active 状态决定发布和评论操作权限；READ 授权只能查询。选题分工不等于账号运营权限。OPS018 在账号 7 的授权于 2026-10-01 失效，账号 12 在快照时暂停，历史内容仍保留。所有日期与事件时间采用 Asia/Shanghai；查询授权日期由可信 `${asOf}` 计算，Action 从可信 `context.now` 换算，不接收冒用的用户或时间参数。

## 指标和数据采集

`metric_definitions` 说明平台口径。短视频播放、图文阅读与订阅内容阅读均按各自平台定义，跨平台汇总可用于工作量参考，不能解释为同口径触达或独立用户。关注数是账号关系数，不做跨账号、跨平台去重。

`account_daily_metrics` 的 new_followers/unfollows 是每日发生量，followers_end 是时点存量，不可跨日求和；某日缺失后，下一份存量仍包含中间真实增减，不能仅用相邻可见日报推断每日增长。

`publication_daily_metrics` 保存平台报告的每日增量及当前修订号，`publication_metric_snapshots` 保存原始累计快照和修订。二者有独立口径：不能将累计快照逐日求和，也不能直接将修订差分冒充每日值。原始快照的反作弊修订可能导致累计值下降，旧快照仍保留。晚到数据在下一日回补，采集时间与业务日期分别记录；`ingestion_batches` 记录完整或部分采集状态。

availability=missing 时，指标为 NULL，表示未获得数据；完整采集但没有发生量才为 0。图文和视频等平台支持自然/付费拆分，订阅内容平台 C 在此示例不提供拆分，因此 organic_views/paid_views 均为 NULL；不可把 NULL 当作自然量 0。可拆分时 views=organic_views+paid_views，禁止再把 views 与 paid_views 相加。

默认模拟内容有长尾衰减、少数第 8 天的二次传播、低互动及移除后的停止采集。评论表是运营工作台抽样，不是完整评论归档；日报评论数可能高于采集的评论正文条数。评论包含待处理、公开、隐藏和已回复，处置记录保留操作者、原因及时间，回复文本只保存在本地。

## 推广、落地与转化

`ad_sets` 关联具体发布和活动，`ad_daily_metrics` 保存消耗、展示、点击及平台报告转化。币种统一 CNY、金额均为整数分；消耗不能超过预算。平台报告转化采用平台自身口径，不能与站内转化事件简单相加。付费和自然内容表现也不直接相加成去重触达。

`tracked_links` 通过匿名跟踪码关联发布、活动及落地页。`landing_daily_metrics` 保存浏览量与会话，不等同于唯一人数。`conversion_events` 表示报名或留资，不包含电话、邮箱或用户标识。event_key 用于采集去重；quality=duplicate 表示不同事件键识别出的重复业务线索，不计入有效转化。invalid 为无效线索。

站内采用最后点击七天归因：事件必须发生在点击之后、七天以内，且有对应落地记录。unknown 表示无法确认渠道，保留 link_id=NULL，不能强行分配给某账号。有效转化只统计 quality=valid，未知归因单列。此数据不用于证明营销因果关系；示例不进行跨平台用户追踪。

所有查询均受当前身份的可见范围过滤，局部活动和账号汇总不能当作全品牌总量。漏斗应按同一时间、同一账号范围及同一事件口径比较，不要求评论、播放、点击、会话与转化在不同系统间逐项相等。

## 角色与权限

| 角色 | 查询范围 | 操作 |
| --- | --- | --- |
| 管理员 OPS001 | 全部业务记录 | 分工、审核及账号操作 |
| 负责人 OPS002 | 有效授权账号及所属团队内容 | 审核、调整编辑，具备 OPERATE 时排期和评论处置 |
| 分析员 OPS003 | 有效授权账号的表现、推广成本和归因数据 | 只读 |
| 编辑 OPS004 | 本人负责的选题、版本及对应发布和效果 | 提交本人内容 |
| 账号运营 OPS005 | 有效授权账号的发布、效果及评论 | OPERATE 授权内排期、记录模拟发布结果、处置评论 |
| 外部协作 OPS006 | 明确分配给本人的选题、版本、发布任务和效果 | 提交分配内容；不看推广成本和内部评论处置 |

OPS007/OPS009 等属于另一品牌团队，用于验证跨团队隔离；OPS017 只有 READ，OPS018 的授权过期，OPS020 账号停用。未知或停用身份拒绝查询。推广表仅管理员、负责人和分析员可读，内容权限不会扩大成本权限。

## 操作与边界

六个需要本人确认的 Action：提交版本、审核版本、排期、记录发布结果、处置评论、调整负责编辑。所有操作只更改本地演示数据，不调用真实平台，不发送评论或执行真实发布。先在「动作工作台」试运行并检查写计划，再由对应账号本人确认。录入发布成功或失败只适用于到达计划时间的 scheduled 任务；不能给任意历史或未来任务伪造发布结果。外部发布号使用 SIM- 前缀。

边界包含拒稿、未来排期、发布失败、下架、暂停账号、授权到期、只读运营、缺失指标、回补修订、累计值下降、不可拆分自然付费、未知归因和重复线索。生成器检查品牌平台归属、流程历史连续性、指标日期与批次、推广预算、归因窗口、评论父子关系等一致性。回归测试使用隔离库验证正常提交、预览回滚、拒绝和越权场景。
