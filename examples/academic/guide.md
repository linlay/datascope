# 高校教务业务与统计口径

本例描述虚构的澄江应用技术学院，便于检验教务查询和受控操作。使用共享课程池的简化本科培养方案，不代表真实院校规章或国家教学标准。

## 学期、教学与校历

春季学期：2026-03-02 至 2026-07-05；秋季学期：2026-09-07 至 2027-01-10。每学期 16 周常规教学，第 17 周考试。选课在开学前开始，开学后两周截止；默认快照 2026-11-13 已过秋季选退课期限，因此默认库的选退课 Action 应拒绝。需要演示成功选退课时，创建 2026-09-10 快照并在测试中使用同日可信执行时间；不能通过业务参数伪造时间。

`calendar_days` 显式记录校历：工作日、周末、停课日和考试准备周。示例在春季若干日期及秋季 10 月 1–7 日停课，不安排补课；这是虚构校历，不是官方节假日安排。常规考勤只出现在实际教学日且不晚于快照日。

`classes` 是行政班；`sections` 是某学期的课程教学班，两者不是一一对应。学生通过 `enrollments` 选教学班；教学班通过 `section_teachers` 关联主讲及协作教师，通过 `section_meetings` 关联周次、星期、节次和教室。联合授课只有一位主讲。教室类型分普通教室和计算机实验室；容量、类型与时间占用必须相容。考试地点通过 `exams` 单独排定，调整上课教室不改变已排考试。

## 选课、历史学分与重修

四届学生各 250 人；2026 级学生没有春季选课记录。少量学生处于休学状态，不生成本次在读选课。每个行政班通常修读四门专业必修、一门本院选修及一门跨学院选修，每门 3 学分，学期上限 24 学分。

先修课程依据 `prerequisites`；只接受选课日期前已认定的历史学分，或已经完整发布、加权总分达到 60 的历史课程。`prior_credits` 是本示例覆盖期之前的历史成绩导入，不伪造本库之外的学期和选课明细。春季必修未通过的学生不会直接选后续先修课，而会在秋季空闲时段重修。旧学期记录保留，不覆盖失败成绩。少量选修退课记录保留选课日、退课日；退课后不继续生成考勤。

选课 Action 检查本人在籍状态、选课窗口、教学班状态、真实总人数、重复课程、学分上限、先修学分及课表冲突。选满教学班和已停开教学班均不能选入。退课只能处理本人的 enrolled 记录，且窗口未关闭、尚未录入成绩。重新选回已退教学班会重新启用原记录并补齐待录入成绩。

## 成绩与统计

每个教学班有作业 30%、期中 20%、期末 50% 三项考核，权重合计 100。分数为整数百分制；缺考记 absent、分数 0；pending 的分数为 NULL，不能作为 0 计入平均分。学生有稳定的合成学习水平，各考核在其基础上波动，体现优秀、普通、未通过和缺考的差异。

成绩先录入 `grades`，再由主讲教师通过 `grade_releases` 发布。只有所有未退课学生的该项成绩齐备且考核日期已到，才可发布。协作教师可录入本教学班成绩，不能发布。发布后锁定，本例不提供撤回和改分审批流程；不能直接用录入 Action 修改已发布成绩。

完整课程总分为 `SUM(score*weight)/100.0`，仅在该课程全部考核已经发布且权重合计 100 时计算；通过线为 60。不同教学班、重修次数分别计算，不把不同学期同一课程的分项成绩混合。待录入和未全部发布课程不参与课程通过率。

查询始终受当前身份的行权限约束。示例中的选课人数是「可见选课人数」，教师或学生看到的部分记录不能当作全校总人数或真实剩余名额。选课 Action 会用事务内的全量人数验证容量，不依赖界面聚合值。

## 五类身份权限

| 角色 | 可见数据 | 允许操作 |
| --- | --- | --- |
| 学生 | 本人选课、考勤、历史学分及已经发布且发布时间已生效的成绩；公共课程和课表目录 | 窗口内选课、退课 |
| 教师 | 本人授课教学班的选课、考勤及成绩，包含草稿；所教学生基本资料 | 授课班级录入成绩，主讲发布成绩 |
| 辅导员 | 有效任职行政班的学生、选课、考勤、历史学分和已发布成绩 | 不授予教务写权限 |
| 学院教务员 | 本学院学生的学习记录；公共目录 | 调整本学院课程的上课教室 |
| 教务管理员 | 全校学习记录和公共目录 | 调整教室；不冒用教师发布成绩 |

辅导员范围按 `${asOf}` 的中国业务日期计算，valid_from 含起始日、valid_to 不含结束日。行政班 4 于 2026-10-01 从 F2001 交接给 F2002，便于检查生效日边界。查询授权生效时点由平台注入；Action 使用可信 `context.now` 转换到北京时间计算办理日期。学生和辅导员的成绩可见性同时受发布时间约束。

`student_contacts` 只向本人、有效辅导员、学院教务员和教务管理员开放；授课教师不读学生私密联系方式。紧急联系人字段不向任何业务查询身份开放。`users` 业务目录仅本人和教务管理员可读；教师目录与授课关系单独开放。不在职教师 1080 与未知身份均拒绝业务查询及操作。查询可见范围不授予写入权限，Action 独立校验身份及归属。

## 边界与验证

包含联合授课、满班、空选修班、停开教学班、休学、退课、先修未通过与重修、缺考、未录入及未发布成绩。生成器检查外键、考核权重、成绩归属与作者、发布完整性、选课人数与学分、教室类型、师生和教室课表冲突、先修学分、考勤校历以及考试冲突。

Action 均需本人确认：先在「动作工作台」选择身份试运行，检查计划与拒绝原因，再以相应业务账号正式调用并确认。管理员拥有查询能力不意味着可以代替学生选课或代替教师改分。重复正式请求使用同一个 request_id 查询执行结果。
