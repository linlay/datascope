# 高校教务演示数据库

面向使用者的描述和使用说明维护在 `bundle.yml` 中，导入后可在控制台点击“使用说明”阅读。正文提供自然语言提问、连续追问、角色视角、业务操作与结果解读；本 README 保留创建、维护和回归说明。

一所虚构的「澄江应用技术学院」：5 个学院、10 个专业、40 个行政班、1,000 名学生、80 名教师和 10 名辅导员。覆盖 2026 年春季已结课学期和秋季在读学期；默认快照为 2026-11-13。姓名、联系方式、课程安排和成绩全部虚构，不代表任何真实院校或官方校历。

## 创建和导入

在仓库根目录执行，生成工具只依赖 Python 标准库，拒绝覆盖已有文件，失败清理新文件：

```sh
make init-academic
# 也可生成另一份快照（2026-09-02 至 2026-12-27）：
python3 examples/academic/generate.py --db /tmp/academic-september.sqlite3 --as-of 2026-09-10 --seed 20261113

# 先设置 DATASCOPE_EXAMPLE_PASSWORD（至少 12 字符），再显式导入：
make check-example EXAMPLE=academic
make import-example EXAMPLE=academic
```

导入提供五种演示身份：ACA001（教务管理员，1）、ACA002（信息学院教务员，2）、T1001（教师，1001）、F2001（辅导员，2001）、202301001（学生，10001）。密码从环境变量读取，不写入配置包；服务启动不会创建此库或账号。已有登记不会被重复导入覆盖。本地当前保留证券、区域销售、高校教务、渠道与社交媒体运营四个演示数据库。

## 内容

- `schema.sqlite.sql`：24 张表、外键、约束和查询索引。
- `generate.py`：固定种子的虚构造数及 22 项关系一致性检查，输出大小、行数和快照日期。
- `rewrite.yml`：学生本人、授课教学班、有效辅导员任职及所属学院范围；未发布成绩对学生和辅导员隐藏，紧急联系人不开放。
- `actions.yml`：选课、退课、录入成绩、发布成绩、调整教室；全部要求本人确认。
- `sql-examples.yml`：九个查询，覆盖课表、成绩、考勤、通过率、空教学班、联合授课、考试和重修。
- `guide.md`：表关系、统计口径、简化边界、权限与操作步骤，作为业务知识文档导入；面向使用者的使用说明单独维护在 `bundle.yml`。

本地库约 14 MiB，含约 1 万条选课、3 万条分项成绩和 12 万条考勤，具体数量随随机种子与快照日变化。所有业务表和字段都有中文结构注释。秋季期末考试是未来的排考安排，期末成绩保留为 pending，不生成未来考勤或评分。

## 回归

```sh
python3 -m unittest discover -s tests/examples -p '*_test.py'
go test ./tests/examples/academic ./internal/configbundle ./tests/architecture -count=1
```

Go 测试使用隔离数据库验证权限、全部 SQL 示例及 Action 的预览、提交、越权拒绝和回滚。实际本地库不会被测试写入。
